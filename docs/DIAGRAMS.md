# Diagram sources

Where each diagram's nodes, arrows and conditions come from. Written for DOC-09 and corrected in DOC-10 (2026-10-22) after reading the source and tests listed here. If code changes, re-check the matching row. Evidence words: **source** (read in code), **test** (a unit or browser test asserts it), **owner evidence** (screenshots recorded in [SENTRY_HANDOFF](SENTRY_HANDOFF.md)), **measured** (a recorded measurement), **unknown** (not established; the diagram says so).

## User guide (`ui/docs.html`, served at `/docs`)

| Section · figure | Shows | Evidence |
|---|---|---|
| 01 · architecture (`.arch`) | Browser ↔ server routes; ledger modules; only `model.py` calls Ollama (`/api/chat`, `/api/tags`); optional outbound tracing drawn separately | source: `server.py` `do_GET`/`do_POST`, `PAGES`, bind address; `ledger/model.py` `OLLAMA`, `extract`, `available_models`; `ledger/tracing.py` `init`; test: `tests/test_pages.py` |
| 01 · one run (`cap-run`) | Load → parse → read → resolve → ledger → review → export; resolve/ledger re-run every 5 messages and after each decision | source: `ui/app.js` `run()` (`i % 5 === 4`), `scheduleResolve`, `onClick`, `resolveNow` |
| 02 · page start (`cap-boot`) | On every page load, for any reader: `GET /api/status` → Ollama `GET /api/tags` (2 s). At least one installed model → menu lists all, `gemma4:e2b-it-qat` preselected if present. Empty list (down, slow or no models) → "only Rules only will work" and the menu shows the default name | source: `ledger/model.py` `available_models` (timeout 2, `[]` on `OSError` or no models), `server.py` `status`, `ui/app.js` `init` (fallback `[st.default_model]`, `selected` on the default) |
| 02 · readers (`cap-readers`) | Model + rules: model and rules both read, `hybrid.merge` flags disagreement and adds rules-only cancellations; Model only; Rules only (no model, skips senders not on the roster); 300 s timeout, no retry | source: `server.py` `_suggest`, `ledger/hybrid.py` `merge`, `ledger/rules.py` `extract`, `ledger/model.py` `extract`; download size measured: [evaluation/RESULTS.md](../evaluation/RESULTS.md) (4.3 GB); Python 3.12/3.15 test runs: [TESTING.md](../TESTING.md); 3.10/3.11 **unknown** (stated, not tested) |
| 03 · parsing (`cap-parse`) | Blank/# lines skipped; three formats start a message; other lines join the previous one or are ignored; sort, ids, duplicates within 24 h; Monday and "no dated messages" stops keep the session | source: `ledger/messages.py` `parse_messages`, `mark_duplicates`; `ui/app.js` `run()`; tests: `tests/test_ledger.py` `Duplicates`, browser `session_rerun.mjs` |
| 03 · roster (`cap-roster`) | One per line, case-insensitive de-duplication, first 20 kept without a warning | source: `ledger/messages.py` `parse_roster`, `server.py` `MAX_VOLUNTEERS`; the missing warning is task COR-06 |
| 04 · copied words to a record (`cap-resolve`) | Who: roster match → resolved / ambiguous / unknown; Day: send date + week → resolved / ambiguous / outside / unreadable; Time: range, period, open, unstated (whole day for cancellations, earlier hours or 09:00–20:00 for offers), unreadable | source: `ledger/names.py` `match_person`, `similar_names`; `ledger/resolve.py` `resolve_day`, `resolve_time`; `ledger/core.py` `_span`, `build_ledger` (unresolved claims `continue`, `review_marks`); tests: `tests/test_ledger.py` `Days`, `Times`, `Names`, `tests/test_d31_fixes.py` |
| 04 · evidence check (`cap-evidence`) | Quote and words both missing → not applied; one missing → flagged, counts while pending; quote not mentioning the days → narrowed or not applied; coordinator self-message → not applied; only while pending | source: `ledger/core.py` `resolve_claim` (drop block), `build_ledger` (`check_wording`); tests: `tests/test_review_safeguards.py` |
| 04 · time ruler and day table | Period hours, open ranges, "at 9" unread; each day row | source: `ledger/resolve.py` `DEFAULT_PERIODS`, `Calendar.day_start/day_end`, `_tok_minutes`; tests: `tests/test_ledger.py` lines for every day row and for "10:30 to 1", "after 3", "4 onwards", "at 9" |
| 05 · a card's life (`cap-card`) | pending → accepted (Accept, A, edit) / rejected (Reject, R) / not applied (code); not applied → accepted ("Use it anyway" or a field edit) or rejected (R key); accepted ⇄ rejected (Accept/Reject, A/R); Reset → pending; added records start accepted; A does not accept a not-applied card | source: `ui/app.js` `review()`, `onFieldChange` (sets `accepted` on any card), `onClick` (`add`, `restore`), `onKey` (only `a` is blocked for dropped; `r` rejects), `card()` (Accept/Reject on every non-dropped card); `ledger/core.py` `resolve_claim` |
| 05 · where each card counts (`cap-count`) | On-screen sheet uses pending + accepted; final sheet reconciles accepted cards (later accepted corrections or cancellations replace or remove time; cells of unreviewed messages are `needs_review`), pending ones only mark cells; review log accepted, pending only with the checkbox; rejected and not applied nowhere | source: `ledger/core.py` `build_ledger` (`live`), `ledger/export.py` `confirmed_export`, `ui/app.js` `buildCsv`; tests: `tests/test_export.py`, browser `sheet_display.mjs` |
| 05 · message marks (`cap-mark`) | Toggle by M or button; deciding cards never marks; marks help determine complete vs provisional status and which cells are `needs_review` (`confirmed_export` touches cells of accepted or pending claims from unreviewed messages), never inclusion, and never block download; the one combined action and its exact conditions; "Accept all suggestions without warnings" never marks | source: `ui/app.js` `toggleReviewed`, `bulkEligible`, `renderRows`, `acceptClean`; test: `tests/test_export.py` `test_deciding_every_suggestion_is_not_review`; browser `review_safeguards.mjs` |
| 05 · failures (`cap-fail`) | Request failure or unreadable reply → per-message warning, reading continues, no retry, never bulk-reviewed | source: `ui/app.js` `run()` (`state.failures`), `failureText`, `renderRows`; `ledger/model.py` `extract` (`json_ok`); browser `extraction_failures.mjs` |
| 06 · status gates (`cap-gates`) | complete only if all non-duplicate messages marked, nothing pending, no who/date/time/conflict issue; provisional still downloads | source: `ledger/export.py` `confirmed_export`, `BLOCKING`, `final_csv`; `ui/app.js` `exportFinal`; tests: `tests/test_export.py` `ConfirmedExport` |
| 06 · how each file is made (`cap-files`) | Final sheet built on the server from accepted claims through `build_ledger`; review log built in the browser, one row per card per date | source: `ledger/export.py`, `ui/app.js` `buildCsv`, `exportCsv`; browser `csv_safety.mjs` (both files) |
| 07 · where data goes (`cap-where`) | Local: browser memory ↔ stateless server ↔ Ollama on 127.0.0.1, CSVs saved by you. Replay: set A only, saved outputs, rules live, 403 for anything unserved, no tracing. Tracing: opt-in, from the local server only, two allowlists; Sentry-side enrichment seen and partly filtered | source: `server.py` `DEMO`, `check_demo`, `parse`, `saved_output`, `log_message`, start-up order (demo returns before `tracing.init`); `ledger/tracing.py` `scrub`, `clean_envelope`; tests: `tests/test_demo_mode.py`, `tests/test_tracing.py`, browser `demo_mode.mjs`; owner evidence: geo values filtered after settings (SENTRY_HANDOFF §1); **unknown**: full received-payload audit, what Render's platform logs |
| 07 · how long a review lasts (`cap-life`) | Reload/close loses it; a run that parses replaces it; a run that fails keeps it | source: `ui/app.js` `state`, `run()`; browser `session_rerun.mjs` |
| 08 · developer map (`cap-devmap`) | Part → code → route → tests → doc | file list of `ledger/`, `server.py`, `ui/`, `tests/`, `tests/browser/`, `evaluation/` |
